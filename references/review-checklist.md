# Patch AI Review 检查清单（arcwrt-luci）

> 用途：本文件内容可直接作为 **subagent 的评审指令**，连同 `git diff --cached` 全文一起交给它。
> 评审对象：**暂存区** diff。

## 评审者行为约束

- **只读**：不改文件、不 commit、不 push、不再往下委派
- 只报**本次改动引入的、可复现的、作者知道了就会去修的**问题
- **不报**：推测性担忧、改动前就存在的老问题、纯风格偏好、刻意为之的行为变更
- 每条问题必须能给出**触发它的具体场景或调用路径**；给不出就不要报
- 走完整份 diff，不要找到第一个问题就停

---

## A. 夹带检查（先看这个，最高优先级）

- [ ] `git diff --cached --name-status` 里每个文件都**属于本次需求**
- [ ] 无 `.bak` / `.bak.arc` / `.bak.<日期>` 混入
- [ ] 无 `combined.patch` / `context-jian` / `.sync_openwrt/` 等产物
- [ ] 无**无关页面**（本次没碰的菜单）被顺带改动
- [ ] 无整文件级格式化 / 换行差异（diff 行数远超实际逻辑改动量）

## B. 调试残留

- [ ] 无 `console.log` / `console.debug` / `alert(` / `debugger`
- [ ] 无 `TODO` / `FIXME` / `XXX` / `测试用` / `临时`
- [ ] 无硬编码测试值（测试 IP、测试账号、固定 MAC/SN、写死的桩数据）
- [ ] 无被注释掉的旧代码块
- [ ] 无临时放宽的校验（注释掉 `disabled`、跳过 `vendor_validate`、放开上限）
- [ ] 无遗留调试开关 / `.only`

## C. 两端口径一致性（本工作流特有，最易漏）

- [ ] 阶段 2 改动台账里**每个**路由器改动，都能在 diff 里找到对应源码改动
- [ ] 没有"只改了路由器没改源码"或"只改了源码没改路由器"的**单边文件**
- [ ] 压缩版 ↔ 可读版的**对应位置**正确（不是改了同名但不同位置的函数）
- [ ] 算法 / 常量两端**一致**，不是近似值

## D. 语言文件

- [ ] 新增 / 改动的 UI 文案在 `htdocs/lang/en/*.js` 有对应词条
- [ ] 改的是 `/www`（可写 overlay）对应的源，不是只改了 `/rom` 侧
- [ ] 词条 key 命名与既有风格一致

## E. 语法与结构

- [ ] `.htm` 内嵌 JS 提取后用 `node --check` 通过
- [ ] **函数边界完整** —— 历史事故：sed 删除范围不精确曾误删下一函数，导致 `Illegal return statement`
- [ ] 无文件末尾换行差异（本地重建后 `md5sum` 与路由器侧比对，差异常是换行）
- [ ] `md5sum` 与路由器运行态一致

## F. 配置链路

- [ ] 新增前端配置项在 `cgi/*.js` 里有对应 `ABS_MAP` 条目
- [ ] 新增 UCI option 在 `package/base-files/files/etc/uci-project/<name>` 有出厂默认
- [ ] 若是"虚拟假配置"需求：假值合理，且**注释标明是假配置**
- [ ] 子网 / 池计算正确：`ipcalc.sh` 按子网主机位算 start 偏移（/16 支持 >255）；
      池 `start` 存**相对网络地址的完整偏移**、`limit` 存**完整 IP 差**，**不能用末段相减**
- [ ] 未破坏"按掩码锁定"设计（掩码 `255` 段锁定、其余可编辑）
- [ ] 表单提交链完整：`getCfg/setCfg` → `subForm()` 加密 POST → `apply_abstract.cgi` → `arc_cgi.lua` 写 UCI

## G. 安全

- [ ] 无明文凭据 / 密钥 / token
- [ ] 无 XSS：拼接进 HTML 的用户输入有转义
- [ ] 无新增调试后门（隐藏入口、万能密码、跳过鉴权）

## H. 提交卫生

- [ ] 暂存区**仅**含本次文件（`git status --porcelain` 中 `^[MADRC]` 行数 == 预期）
- [ ] 未使用 `git add .` / `-A` 的痕迹（未跟踪垃圾仍在 `??` 状态）
- [ ] commit message 只描述**实际改了什么**，无夸大、无漏述

---

## 输出格式

先列问题、按严重度排序，每条一格：

```
[P1] <祈使句标题> — <path/to/file>:<line>

<一段说明：触发场景 + 为什么是错的>
```

引用范围尽量小，且**必须落在被评审 diff 内**。

| 级别 | 含义 | 门 4 处置 |
|---|---|---|
| `P0` | 发布阻塞 / 严重故障 | **阻塞**，必修 |
| `P1` | 紧急缺陷，应立刻修 | **阻塞**，必修 |
| `P2` | 普通缺陷，应该修 | 逐条问用户 |
| `P3` | 低影响，仍值得修 | 记录，不阻塞 |

无合格问题就写 **`No findings.`**——不要为了填满报告硬凑问题。

最后附一句总体评估，并点出**测试缺口与残余风险**。
